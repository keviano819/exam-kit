# Vercel 上传指南：从注册到手机访问

选择 `vercel` 时读取。将本指南按当前产物定制后，作为 `Vercel上传指南.md` 交付给用户，而不只是留在 skill 内部。将示例名称换成本次实际文件名、发布目录、版本和校验结果；团队、项目名与线上地址未知时让用户在操作中选择，不编造。完整教程放在文件，聊天中只给入口与当前下一步。

流程核实日期：2026-11-05。交付教程前重查末尾官方来源；按钮变化时以当前界面为准。默认由用户人工完成账户和上传操作，AI 负责打包与验收，不要求先安装 Git、GitHub 或 CLI。

## 1. 你会拿到哪些文件

AI 应先交付部署 ZIP、同内容的发布文件夹和本指南。示例结构如下，实际清单必须与本次包一致：

```text
vercel-deploy/
  index.html
  data.js
  manifest.json
  sw.js
复习工作台-vercel.zip
Vercel上传指南.md
```

以上是当前构建器默认的四文件静态版本，不是永久固定清单：深度正文已合入 `data.js`；如果课程需要本地图像、样式或其他离线资源，发布清单会增加。ZIP 解开后根部直接有 `index.html`，不要把整个课程工作目录套在外面。教程放在 ZIP 外。

打包前由 AI 检查：

- 首页引用的每个资源都已打包，`data.js` 中包含深度讲解数据。
- 题库、正文和缓存版本一致；有 Service Worker 时其预缓存列表包含实际必要文件。
- 不含 `.env`、密钥、个人学习记录、学习者背景、私密笔记、日志、原始课件和无关文件。正文中也不应夹带私人经历或身份信息。
- 所选公开内容具有适当传播权限；没有原始 PDF 不代表生成内容可以不加判断地公开。
- 发布包是可直接使用的静态输出，不需要用户编译或启动服务器。

## 2. 注册或登录 Vercel

1. 在电脑浏览器打开 https://vercel.com/signup 。已有账号则打开 https://vercel.com/login 并沿用原账号，避免把更新传到另一个团队。
2. 选择页面实际提供的邮箱或 Git 服务账号方式。没有 GitHub 也可以用邮箱注册，不必为了这份静态工作台先创建代码仓库。
3. 若用邮箱，填写自己的邮箱，在邮件里查看验证码并回到 Vercel 输入；若要求额外身份或手机号验证，由本人在页面完成，不把验证码或密码交给 AI 保存。
4. 若出现用途和套餐选择，个人非商业复习可考虑 Hobby；商业用途应检查当前套餐要求。Hobby 并非无限资源，不能承诺永久免费或无流量限制，也不需要为这份简单工作台默认购买域名、试用付费功能或填写支付信息。
5. 完成后进入 Dashboard，记住当前工作区/团队名称。

成功标志：能看到自己的 Dashboard 和工作区。注册、验证尚未完成时停在这里，完成后再上传。

## 3. 首次发布：上传部署包

1. 保持登录状态，打开 https://vercel.com/drop 。本路线先登录再发布，不依赖未登录的临时、会过期部署。
2. 将 AI 交付的部署 ZIP 拖入页面。也可使用页面提供的文件或文件夹选择入口；只上传发布包，不能拖入包含 PDF 和笔记的整个课程目录。
3. 检查上传文件列表是否与 AI 给出的清单一致。特别检查 `index.html` 和深度正文资源，发现遗漏先返回重新打包。
4. 选择自己的团队，填写容易辨认的项目名，例如 `my-exam-kit`。保留页面接受的可用名称；名称冲突时换一个，不承诺示例域名必然可用。
5. 若出现首页选择，选 `index.html` 为根页面 `/`。如果列表中没有它，先检查 ZIP 层级，不要选“无首页”。
6. 本工作台是纯静态文件；通常无需设置构建。若出现设置页，框架选择 `Other`，构建命令留空，输出目录指向实际静态根目录；不要照抄不存在的 `dist` 或 `npm run build`。
7. 核对目标后点击 `Deploy`。若再次要求验证码，由本人完成后查看页面状态，必要时返回继续提交；不能仅凭“验证码正确”就认定发布完成。
8. 等到部署状态为 `Ready` 或页面明确显示完成，再点 `Visit` 打开网站。若报错，保存错误文字或截图，交给 AI 处理，不连续点击部署。

## 4. 获取分享链接并在手机检查

从项目 Overview 的 `Domains` 或 `Visit` 获取该项目的生产地址，一般是分配给项目的 `https://项目名.vercel.app`。不要分享 Vercel Dashboard 管理地址，也不要随手复制旧版本的临时部署地址。

把生产链接发到手机，用 Safari 或 Chrome 打开。检查首页、各单元正文、题目提交、错题和记录导出。若需要桌面快捷入口，可在浏览器菜单中查找“添加到主屏幕”；这是可选项，不保证所有设备都显示安装按钮，也不等于已具备完整 PWA 离线能力。

分享给别人之前，用未登录 Vercel 的浏览器或设备试开链接。如果要求登录，检查是否复制了受保护地址以及项目的 Deployment Protection 设置；不要为了访问方便擅自关闭保护，先决定课程是否应公开。

成功标志：目标手机能打开生产链接，看到本次课程版本，讲解和答题正常。只有实际验证这些项目，AI 才能说“线上验收通过”。

## 5. 更新原项目，保留原链接

1. 由 AI 生成新的完整发布包，保持课程和题目 ID，更新内容与缓存版本。更新前建议导出学习记录备份。
2. 登录原账号，在 Dashboard 找到原项目，核对项目名和原域名，进入 **原项目 Overview**。
3. 对没有 Git 连接的 Drop 项目，将新版发布文件夹拖入这个项目页。当前界面若支持 ZIP，可直接拖新版 ZIP；若不接受，先解压，再拖只含发布资源的文件夹。
4. 在 `New Production Deployment` 确认页核对它指向原项目，并确认文件清单正确，再点 `Deploy to Production`。这一步会替换该项目对外服务的版本。
5. 完成所需验证，等待 `Ready`，检查项目生产域名仍是原链接，再打开它确认新增章节或版本标记。

**更新不要回到通用的 `/drop` 或 `/new` 入口重新创建项目**，否则可能拿到新项目和新域名。不要删除原项目来“更新”。只点击旧部署上的 `Redeploy` 也不能把电脑上尚未上传的新文件带到线上。

若原项目已经连接 Git，或界面没有项目内 Drop 更新入口，应停下核对原部署方式。由 AI 给出适配该项目的 Git 或已链接 CLI 步骤，不能盲目运行 `vercel --prod --yes` 创建另一个项目。不要在本教程的简单上传路线中默认安装工具或新建凭据。

## 6. 学习记录与离线边界

这个静态工作台分享的是课程和交互，不提供跨设备账号同步。电脑、手机、不同浏览器及不同域名有各自的浏览器记录；登录 Vercel 管理账号不会把学习进度同步过去。

同域名、同浏览器、同存储键的兼容更新通常可继续读取原记录，但不承诺永不丢失。更换域名、隐私浏览、清除网站数据或浏览器回收存储都可能影响记录。使用工作台的导出备份；仅在产物实际有导入功能时说明恢复步骤，不把导出功能称为已实现同步。

手机首次打开需要网络。有完整缓存功能的版本，在成功加载必要资源后可能离线使用；必须经过断网实测才能承诺。未做离线缓存的版本按在线工作台交付。

## 7. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 首页 404 | 查看发布包根部是否有 `index.html`，首页映射是否为 `/`，访问的是否是正确项目 |
| 能打开首页，学习内容为空 | 检查正文 JS 是否上传、引用路径与大小写是否一致；把控制台错误交给 AI |
| 手机还显示旧内容 | 先核对生产地址和线上版本；关闭该网站所有标签页及主屏幕窗口后再打开。仍未更新时由 AI 检查 Service Worker。不要先清除全部网站数据 |
| 验证后停住 | 查看是否已返回部署页、是否仍需提交；只有 `Ready` 才表示这次部署完成 |
| 别人打开要求登录 | 核对地址与部署保护；由用户决定是否允许公开访问 |
| 手机显示 0% | 可能只是该设备尚无本地记录，不表示电脑上的记录被删 |
| 看到代码或下载文件，没显示网页 | 确认打开生产根地址，不是 `data.js` 或 ZIP 的链接 |
| 出现付费、升级或额度提示 | 停下查看当前套餐与限制，不为完成部署自动购买升级 |

## 8. 交给 AI 做最终验收

上传完成后，把生产链接和“上传完成”发给 AI 即可，不需要提供验证码或账号密码。AI 检查生产状态、资源可访问性、正文和题库版本，并区分已实测项与未实测项；单次只读验收不修改答案或清空进度。
